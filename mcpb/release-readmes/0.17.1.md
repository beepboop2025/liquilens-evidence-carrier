# LiquiLens Evidence Carrier 0.17.1

This immutable-per-version bundle README describes the bytes prepared for the
v0.17.1 MCPB candidate. Its presence in a source tree or locally built bundle is
not publication proof. Until a successful signed-tag workflow publishes the
bundle with checksums and attestations and the official MCP Registry activates
the exact version, v0.16.0 remains the production pin.

Version 0.17.1 is a new recovery identity. It does not move, replace, or convert
the immutable failed v0.17.0 tag or its prepared bundle README into a release.

## Offline tools

The stdio server exposes four read-only, local-file tools:

- `verify_carrier`
- `project_carrier`
- `verify_fleet_brief`
- `verify_trade_safety_receipt`

It supports MCP `2026-07-28` and `2025-11-25`, makes no network request, accepts
no signing secret, and has no trading, recommendation, capital-allocation,
credit-rating, broker, credential, or execution authority. HMAC/live Trade
Safety receipts fail closed in this MCP server and must be verified inside the
tenant boundary.

## Trade Safety v1

The bundle includes strict request, policy, broker-preview-reference, and
receipt schemas; the cross-language `liquilens-hash-tree-v1` verifier; and the
two FDC3 Trade Safety JSON assets. A receipt binds one exact proposed order,
operator policy, independent Seiche/Undertow/conditional LiquiLens evidence,
clocks, rights, broker-preview state, deterministic outcome, expiry, issuer, and
all-false authority boundary.

Hash-only receipts are tamper-evident but unauthenticated and cannot produce a
live pass. A `pass` means only that the exact embedded request satisfied the
exact embedded operator policy; it is not advice, approval, an order, an
executable quote, or a promise of fill. Execution adapters must verify again at
the current clock and atomically reject replayed receipt IDs.

The networked Trade Safety sandbox is a separate integration artifact. It is
not embedded in or started by this offline MCPB and is not covered by the
Registry declaration `networkAccess:false`.

## Publication verification

Before treating a downloaded bundle as v0.17.1, verify all of the following:

1. the signed annotated tag, its exact allowlisted SSH-signed candidate commit,
   and that commit's protected-main ancestry;
2. the successful release workflow and provenance attestations;
3. the bundle digest against the published `SHA256SUMS`; and
4. the active official MCP Registry 0.17.1 record against the same artifact.

No such publication receipt is asserted by this candidate README.
