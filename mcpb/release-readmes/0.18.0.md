# LiquiLens Evidence Carrier 0.18.0

This immutable-per-version bundle README describes the bytes prepared for the
v0.18.0 MCPB candidate. Its presence in a source tree or locally built bundle is
not publication proof. Until a successful signed-tag workflow publishes the
bundle with checksums and attestations and the official MCP Registry activates
the exact version, v0.17.1 remains the production pin.

Version 0.18.0 adds authenticated agent-facing gateways around a fail-closed,
paper-only order guard in the Python library. The MCP server remains read-only
and exposes no order, broker, credential, signing-key, or execution tool. The
separately packaged networked gateway is not embedded in or started by this
offline MCPB.

## Offline tools

The stdio server exposes four read-only, local-file tools:

- `verify_carrier`
- `project_carrier`
- `verify_fleet_brief`
- `verify_trade_safety_receipt`

It supports MCP `2026-07-28` and `2025-11-25`, makes no network request, accepts
no signing secret, and has no trading, recommendation, capital-allocation,
credit-rating, broker, credential, or execution authority. HMAC/live Trade
Safety receipts fail closed in this MCP server and must be verified inside the
tenant boundary.

## Trade Safety v1 and order guard

The bundle includes strict request, policy, broker-preview-reference, and
receipt schemas; the cross-language `liquilens-hash-tree-v1` verifier; and the
two FDC3 Trade Safety JSON assets. The schema identities and v1 semantics are
unchanged from v0.17.1.

The bundled Python source also contains the paper-only order guard. Its
agent-facing gateway accepts only tenant-authenticated HMAC receipts, binds the
exact request, account, policy, issuer, and execution identity, evaluates with
an operator-owned clock, and rejects replay before invoking a private submit
callback. Live and observation modes remain held. Low-level wiring is not an
agent tool and process-local replay stores are for tests or local paper demos,
not a production durability boundary.

A `pass` means only that the exact embedded request satisfied the exact embedded
operator policy; it is not advice, approval, an order, an executable quote, or
a promise of fill. Production execution adapters must verify at the current
clock, atomically consume receipt IDs, isolate credentials and keys from agent
code, and reconcile uncertain broker outcomes.

## Publication verification

Before treating a downloaded bundle as v0.18.0, verify all of the following:

1. the signed annotated tag, its exact allowlisted SSH-signed candidate commit,
   and that commit's protected-main ancestry;
2. the successful release workflow and provenance attestations;
3. the bundle digest against the published `SHA256SUMS`; and
4. the active official MCP Registry 0.18.0 record against the same artifact.

No such publication receipt is asserted by this candidate README.
