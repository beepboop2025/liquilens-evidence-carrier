# LiquiLens Evidence Carrier 0.17.0

This immutable bundle README describes the bytes prepared for the v0.17.0 MCPB.
Its presence inside a source tree or bundle is not publication proof; verify the
signed tag, GitHub release, checksum, attestation, and official MCP Registry
record independently.

## Offline tools

The stdio server exposes four read-only, local-file tools:

- `verify_carrier`
- `project_carrier`
- `verify_fleet_brief`
- `verify_trade_safety_receipt`

It supports MCP `2026-07-28` and `2025-11-25`, makes no network request, accepts
no signing secret, and has no trading, recommendation, capital-allocation,
credit-rating, broker, credential, or execution authority. HMAC/live Trade
Safety receipts fail closed in this MCP server and must be verified inside the
tenant boundary.

## Trade Safety v1

The bundle includes strict request, policy, broker-preview-reference, and
receipt schemas. A receipt binds one exact proposed order, operator policy,
independent Seiche/Undertow/conditional LiquiLens evidence, clocks, rights,
broker-preview state, deterministic outcome, expiry, issuer, and all-false
authority boundary.

Hash-only receipts are tamper-evident but unauthenticated and cannot produce a
live pass. A `pass` means only that the exact embedded request satisfied the
exact embedded operator policy; it is not advice, approval, an order, an
executable quote, or a promise of fill. Execution adapters must verify again at
the current clock and atomically reject replayed receipt IDs.

The networked Trade Safety sandbox is a separate integration artifact. It is
not embedded in or started by this offline MCPB and is not covered by the
Registry declaration `networkAccess:false`.
