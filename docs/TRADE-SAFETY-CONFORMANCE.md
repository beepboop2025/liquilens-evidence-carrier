# Trade Safety v1 conformance and threat model

This release adds an adversarial, raw-byte corpus for independent consumers of
the unchanged `liquilens.trade-safety-receipt.v1` schema. The corpus is
deterministically generated by the released Python implementation and checked
by the dependency-free Node/TypeScript consumer.

## Protected boundary

The reference order guard protects exactly one paper-order callback. It assumes
the operator controls the callback, HMAC key, trusted issuer binding, clock, and
atomic receipt-claim store. It verifies the receipt and claims it before the
callback runs. There is no broker client, credential discovery, network fetch,
telemetry, automatic resizing, or live-order path in this package.

The authoritative verifier inputs are raw UTF-8 bytes. This protects against:

- duplicate JSON keys being overwritten by a convenience parser;
- invalid UTF-8 being silently replaced;
- integer/float lexeme collapse (`1000` versus `1000.0`);
- loss of integers larger than JavaScript's safe `Number` range;
- content, identity, request, policy, decision, or HMAC mutation;
- cross-account, cross-tenant, cross-agent, cross-policy, or cross-issuer use;
- expired, future, replayed, observation-only, and non-pass receipts; and
- any proposed `live` request, regardless of what the receipt says.

## Explicit non-goals and residual risks

HMAC authentication establishes possession of a tenant-local symmetric key; it
does not establish a public identity. The deterministic corpus key is public and
must never be reused. The in-memory claim store coordinates only one process and
is for tests or local demos. Production-like paper systems need an atomic,
durable operator-owned claim store and their own broker idempotency and
uncertain-outcome reconciliation controls.

The reference implementation does not turn evidence into advice or execution
authority. A valid `pass` means only that the embedded operator-authored policy
was satisfied for the exact paper request at the verified time. Live routing
remains outside the implementation and fails closed.

## Reproduce

```bash
python scripts/generate_trade_safety_conformance.py --check
python scripts/check_trade_safety_conformance.py
```

The generator commits base64-encoded raw inputs so malformed UTF-8 and duplicate
key cases remain byte-exact inside valid corpus JSON. The checker first proves
that the committed corpus is reproducible, then runs every case through the
Node verifier and order guard.
